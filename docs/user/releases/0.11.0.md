## What this release is

0.10.0 made the language ready to write its own toolchain. 0.11.0 is that toolchain: the compiler,
the interpreter, the commands, the test harness and the tests are written in Nazm, and the `nazm` you
download is built by Nazm from Nazm. The Rust implementation that came before it is frozen as the
bootstrap seed — the program that builds the first Nazm-written compiler — and changes only by a
recorded decision of the copyright holder (`docs/internal/seed-freeze.txt`).

As for 0.9.0 and 0.10.0: no compatibility promise until 1.0, and external contributions are not
accepted yet. Language changes since 0.10.0 are in [`../spec.md`](../spec.md); a program that built
with 0.10.0 builds with 0.11.0 unless a changed rule named there says otherwise.

needs the Xcode Command Line Tools on a Mac. Homebrew: `brew install nazm-lang/tap/nazm`.

## What is in it

| Area | What |
| --- | --- |
| The toolchain in Nazm | The lexer, parser and checker agree with the Rust reference on every input they carry; the intermediate representations, ownership and cleanup, the runtime's units and the object cache are identical to the reference's on both Mac targets; the interpreter and every command are ported and compared against the reference |
| Nazm's own code generator | `nazm build --backend nazm` writes Mach-O objects for both Mac targets, checked against LLVM program by program; LLVM stays the default and Cranelift stays available |
| Self-hosting | The compiler built by itself is byte-identical to the build before it (stages 1 to 3), and the self-built interpreter and checker agree with the seed's on the corpus; the build holds a bounded heap |
| A host rule | One Nazm-built program may run on the macOS host, under a counted 2 GiB heap, one at a time and never beside a container; everything else Nazm builds runs only in the container (`xtask host-run`) |
| Windows | The toolchain runs on a real Windows x86_64 machine: programs agree with the Mac builds (`TODO(gate): final counts from the Dell rerun`) |

## What the gate found and fixed

The gate is run to find things. Between 0.10.0 and this release it found, and the release fixes:

- **A recursion that never ended.** A user type that referred to itself made `UserTypes::depth` loop
  (the seed-freeze exemption for it was approved by the copyright holder). The check now stops at a
  cycle and reports it.
- **A fuzz run that could hang unseen.** The fuzz harness gained a watchdog that kills a stuck
  target and reports it.
- **A test that did not test.** The mutation campaign let one mutant survive — the Cranelift
  backend's version string leaving out its optimisation level, so an object built at one level could
  be reused at another. The test compared cache keys that differed for another reason, so it passed.
  It now checks the version string itself, and fails on the mutant. `TODO(gate): any further test
  the final mutation run strengthened`.
- **Windows and arm CI.** Ten tests that need a Unix host are compiled only on Unix; one lock test
  that raced a forking neighbour waits the race out.
